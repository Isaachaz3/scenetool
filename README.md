# VTT Lite

Браузерный стол для очной игры: ведущий работает на своём экране, а на второй экран (монитор, ТВ
или Chromecast) выводится вид для игроков. Всё хранится в браузере ведущего (IndexedDB), по
желанию синхронизируется с облаком Supabase; резервная копия — один файл `.vttlite.zip`.

Готовы **этапы 1 и 2** из ТЗ: подгонка карт под сетку, экран игроков, линейка и движение, указка,
рисование, туман войны, контекстное меню, менеджер хранилища и резервные копии. Плюс облако на
Supabase: войдя в аккаунт, библиотека доступна с любого компьютера. Дальше — удобства этапа 3.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev        # режим разработки: http://localhost:5173
```

Откройте адрес в Chrome или Edge. Вывод на второй экран через Presentation API работает только в
этих браузерах и только на `localhost` или по `https`.

## Сборка и проверка

```bash
npm run build      # проверка типов и статическая сборка в dist/
npm run preview    # раздать dist/ на http://localhost:4173
npm test           # Vitest: DPI, снап, вид, дистанции, бэкап, протокол экрана игроков
npm run lint       # ESLint
npm run format     # Prettier
```

## Деплой

Сайт публикует GitHub Actions (`.github/workflows/deploy.yml`): при каждом пуше в рабочую ветку
он запускает тесты, собирает `dist/` и выкладывает его на GitHub Pages.

Один раз в настройках репозитория: Settings → Pages → Build and deployment → Source — **GitHub
Actions**. Режим «Deploy from a branch» не подходит: он отдаёт исходники без сборки, и страница
остаётся белой. Перезапустить публикацию вручную: Actions → Deploy to GitHub Pages → Run workflow.

`dist/` — обычная статика с относительными путями (`base: './'`), поэтому её можно положить и на
любой другой хостинг, в любой подкаталог.

## Облако (Supabase)

Если войти в аккаунт (меню → «Облако»), сцены, ассеты и картинки синхронизируются с проектом
Supabase и открываются с любого компьютера. Работа по-прежнему идёт в браузере (IndexedDB), а
изменения уходят в облако сами: через несколько секунд после правки, раз в минуту и при возврате
на вкладку. Без входа всё как раньше, только локально.

Один раз в панели Supabase:

1. **SQL Editor** → New query → вставить содержимое `supabase/schema.sql` → **Run**. Скрипт
   создаёт таблицу `vtt_docs`, приватное хранилище `vtt-files` и правила доступа «только владелец».
2. **Authentication → Sign In / Providers** → выключить **Confirm email** → **Save changes**.
   Встроенная почта Supabase пишет только участникам проекта и не чаще нескольких писем в час, а без
   подтверждения аккаунт работает сразу.
3. В приложении: меню → «Облако» → почта и пароль → «Создать аккаунт».
4. Там же, в **Sign In / Providers**, выключить **Allow new users to sign up** → **Save changes**:
   больше никто не заведёт аккаунт в вашем проекте. На другом компьютере — «Войти» с той же почтой и
   паролем.

Если подтверждение почты всё же нужно, в **Authentication → URL Configuration → Site URL** укажите
`https://isaachaz3.github.io/scenetool/` (для разработки — ещё `http://localhost:5173/` в Redirect
URLs): туда ведёт ссылка из письма.

При первом входе на новом компьютере его стартовая коллекция «Default» сливается с облачной, а
пустая «Сцена 1» убирается, если в облаке уже есть сцены. Бесплатный проект Supabase засыпает после
недели без запросов: данные сохраняются, проект будится кнопкой в панели, а до тех пор приложение
работает локально.

Музыке (эмбиенту) нужна обновлённая таблица: если окно «Облако» пишет, что музыка не
синхронизируется, запустите `supabase/schema.sql` ещё раз — он безопасен для повторного запуска.

Сколько места занято, видно в окне «Облако» (и в подсказке над кнопкой «Облако»): картинки из
1 ГБ и база из 500 МБ бесплатного тарифа. Для этого в проекте нужна функция `vtt_usage()` из
`supabase/schema.sql`; если окно просит обновить таблицы, запустите скрипт ещё раз — он безопасен
для повторного запуска.

Адрес проекта и публичный ключ лежат в `src/cloud/config.ts`. Публичный (publishable) ключ можно
хранить в коде: данные защищены правилами доступа, а не секретностью ключа. Секретный ключ в
приложение не кладётся никогда.

## Как пользоваться

- **Сцена из карты** (док → «Сцены» → «Сцена из карты»): выберите экспорт карты, проверьте
  найденную сетку и нажмите «Создать сцену». Сетка определяется по имени файла (`Tavern 30x20.png`,
  `таверна 30х20.png`), затем по DPI в метаданных PNG/JPEG/WebP, иначе берётся 150 DPI с пометкой
  «проверьте выравнивание».
- **Файлы на холст**: перетащите картинку на холст. Широкие (больше 1500 px) становятся картой,
  остальные — персонажем.
- **Ручная подгонка**: в окне «Сцена из карты», в менеджере ассетов или через кнопку «Выровнять по
  сетке» в плашке под выделенной картой. Стрелки сдвигают на 1 px (Shift — на 10 px), `+` и `−`
  меняют DPI на 0,1. Если стороны карты делятся на привычные значения (100, 128, 150…), рядом с
  полями появляются кнопки «150 DPI · 29×22» — нажмите и сразу видно, легла ли сетка.
- **Визуальная подгонка** (кнопка «Визуальная подгонка» там же): 1) щёлкните или перетащите якорь
  на угол любой клетки карты — рядом лупа; 2) тяните ручку, пока четыре клетки рамки не совпадут с
  четырьмя клетками карты; 3) совместите ручку у дальнего края с пересечением линий. Shift держит
  одну ось, Ctrl замедляет в 10 раз, колесо — масштаб, Enter — дальше, Esc — отмена.
- **Экран игроков**: меню слева внизу → «Окно игроков» (открывает отдельное окно, его можно
  перетащить на ТВ и развернуть кнопкой «На весь экран») или «Вывести на экран игроков» (Presentation
  API: второй монитор в режиме «Расширить» или Chromecast).
- **Вид игроков**: кнопка с масштабом сетки («5ft») справа внизу → «Sync View» (клавиша Y) переносит
  ваш вид игрокам, переключатель «Следовать» (Shift+Y) повторяет его постоянно. Пока экран игроков
  подключён, на холсте видна пунктирная **рамка «Экран игроков»**: тяните за край — картинка у
  игроков едет, за уголок — меняется зум (пропорции экрана сохраняются).
- **Скрыть от игроков**: глаз в плашке под выделенным элементом или Shift+H. Скрытое ведущий видит
  полупрозрачным, а на экран игроков оно вообще не передаётся.
- **Измерение**: R — линейка (зажать и тянуть), M — движение (тянуть фишку, за ней тянется линейка,
  Esc возвращает на место). W во время протягивания ставит точку излома — дистанция складывается
  по отрезкам. Метод счёта — в панели слева сверху или в панели сетки.
- **Постоянная линейка**: с линейкой (R) двойной клик — начало, щелчки — изломы, двойной клик или
  Enter — готово (Esc — отмена). Она остаётся на столе у обоих экранов, её можно двигать (H) и
  удалять (Delete).
- **Транспорт и вложения**: персонаж, брошенный на транспорт (слой «Транспорт»), прикрепляется и
  ездит вместе с ним; вложение (статус, снаряжение), брошенное на персонажа, ходит за персонажем.
  Стащили в сторону — открепилось. Ещё — правый клик: «Прикрепить к …» (выделите несколько) и
  «Открепить». Скрытый от игроков транспорт прячет и седоков.
- **Указка** (P): зажатая кнопка мыши показывает игрокам лазерную точку.
- **Рисование** (D): кисть, линия, прямоугольник, круг (от центра), многоугольник (Enter или двойной
  клик — готово), ластик. Рисунок — обычный элемент: выделяется, двигается, скрывается.
- **Туман** (F): прямоугольник, многоугольник, круг, кисть. «Заливка» закрывает всю сцену, а
  разрезанные фигуры открывают области. Щелчок по фигуре — меню «Разрезать / Вернуть». Shift+P —
  посмотреть глазами игроков.
- **Начальный экран** открывается при запуске (и из меню → «Начальный экран»): все сцены с превью
  (свежие первыми, есть поиск), «Продолжить», «Сцена из карты», «Новая сцена», а справа сразу
  «Вывести на второй экран» и «Открыть окно игроков». Галочка внизу отключает показ при запуске,
  Esc или крестик — закрыть.
- **Фоны** (док → «Фоны» → «Добавить»): картинка поверх сцены на обоих экранах. Нажали на фон —
  он появился, нажали ещё раз (или «Убрать», или Esc) — пропал. У игроков фон всегда заполняет
  экран целиком: лишнее обрезается, а кадр сам встаёт на самую детальную часть картинки. У вас фон
  виден целиком, светлая рамка — то, что видят игроки; щёлкните или потяните, чтобы сдвинуть кадр,
  «Авто» вернёт автоматический. «Свернуть у себя» оставляет в углу превью того, что на экране
  игроков, а вы работаете со сценой. Любой ассет можно сделать фоном в менеджере ассетов.
- **Эмбиент** — микшер как в OBS (кнопка с нотой справа внизу). Звуки (ссылки YouTube и аудиофайлы
  MP3, OGG, WAV, M4A, FLAC) лежат в менеджере ассетов → вкладка «Эмбиент». В микшере каждый звук —
  канал с вертикальным фейдером в dB (двойной щелчок — 0 dB), индикатором уровня и кнопкой выключения;
  каналов может играть сколько угодно сразу, все по кругу. «Общие» каналы играют во всех сценах,
  каналы «Сцены» начинаются при её открытии и заканчиваются при уходе; галочка «Глушить общие в этой
  сцене» ставит общие на паузу, пока сцена открыта (например, для боевой музыки). Справа — выход
  (мастер-громкость и пауза). Звук идёт из окна ведущего; у YouTube индикатор уровня не работает —
  браузер не даёт измерить чужой плеер.
- **Правый клик** по элементу — полное меню: слой, подпись под фишкой, размер, копирование и т. д.
- **Хранилище** (меню): сколько занято, ассеты по размеру, удаление неиспользуемых, экспорт и импорт
  резервной копии.
- Полный список клавиш — меню → «Горячие клавиши».

## Устройство

- `index.html` → `src/gm` — окно ведущего, единственный владелец состояния (Zustand + Immer),
  пишет в IndexedDB (Dexie, `src/db`).
- `player.html` → `src/player` — окно игроков: только отрисовка. Данные получает по каналу связи
  (`src/protocol`: Presentation API или `window.open` + `postMessage`) и в IndexedDB не ходит.
- `src/core` — чистая логика: модель данных, геометрия и снап, вид, определение DPI, дистанции,
  история undo, план слияния бэкапа.
- `src/render` — отрисовка на Konva, общая для обоих окон: элементы, сетка, туман, линейка, указка.
- `src/cloud` — вход и синхронизация с Supabase; схема базы — `supabase/schema.sql`.
- `src/i18n/ru.ts` — все строки интерфейса.

Решения, принятые там, где ТЗ молчит, записаны в [DECISIONS.md](DECISIONS.md).

## Этап 1: проверка вручную

1. Карта Dungeon Alchemist, экспортированная при 100, 150 и 200 DPI: «Сцена из карты» должна показать
   «Метаданные PNG: … DPI», а линии карты совпасть с сеткой сцены в дальнем углу при зуме 100 % (поле
   «Зум» в панели «5ft»).
2. Файлы `Tavern 30x20.png` и `таверна 30х20.png`: импортёр показывает «Имя файла: 30 × 20 клеток».
3. Менеджер ассетов → карта с известной сеткой → «Колонки» = 35 и смещение → «Сохранить» → карта на
   сцене совпадает с сеткой.
4. Меню → «Окно игроков»; перезагрузите окно игроков (F5): сцена возвращается меньше чем за 2 с.
5. Монитор в режиме «Расширить» → меню → «Вывести на экран игроков» → выбрать монитор.
6. Фишка → Shift+H: у ведущего полупрозрачная, у игроков пропала.
7. «Sync View» переносит вид; со включённым «Следовать» сдвиг и зум повторяются у игроков.
8. Перезагрузите страницу ведущего: сцены, ассеты, последняя сцена и её вид на месте.

## Этап 2: проверка вручную

1. Фишка, M, протащить на 5 клеток по диагонали при масштабе 5ft: 25ft (Chessboard), 35ft
   (Alternating), 35ft (Euclidean), 50ft (Manhattan). Метод меняется в панели слева сверху.
2. Линейка и движение видны на экране игроков, пока вы тянете.
3. F → «Заливка» и «Новые фигуры разрезаны» → нарисовать прямоугольник: игроки видят только эту
   область, вы — всё сквозь полупрозрачный туман.
4. P → зажать кнопку мыши: точка появляется у игроков почти сразу.
5. Меню → «Хранилище» → «Экспорт копии»; очистить данные сайта (или открыть в другом профиле
   браузера) → «Импорт копии»: сцены и картинки на месте.
6. Ctrl+Z / Ctrl+Shift+Z работают для перемещения, удаления, тумана, рисунков и текста.

## Этап 3: проверка вручную

Взяты пункты: рамка вида игроков, точки излома, постоянные линейки, визуальная подгонка, подбор DPI
по делимости, транспорт и вложения.

1. Карта с неизвестной сеткой → «Сцена из карты» → «Визуальная подгонка», три шага: в дальнем углу
   линии совпадают (расхождение меньше 1 px при зуме 100 %).
2. Подключите экран игроков: перетаскивание рамки «Экран игроков» двигает картинку у игроков, уголок
   меняет зум.
3. R, тянуть 3 клетки вправо, W, 2 вниз: 25ft; двойной клик ставит постоянную линейку.
4. Кружок → правый клик → «Слой: Транспорт», размер 3; второй кружок бросить на него и подвинуть
   транспорт: седок едет вместе.
